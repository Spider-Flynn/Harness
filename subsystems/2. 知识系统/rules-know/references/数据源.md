# 数据源资产

## 范围与存放

维护本项目实际需要的数据源、表结构 SQL 和可复用数据集。以一个核心数据源为主；其他项目的数据源
只登记本项目依赖的库表或样本，不把范围扩大为对方完整数据库。

资产统一放在 `.harness/know/数据源/`：

- `index.json`：唯一索引，开头描述数据源与核心来源，随后登记所需表和数据集。
- `<数据源>/schema/`：需要保存的表结构或 DDL，使用 `.sql`；必要时在文件路径中区分库和 schema。
- `<数据源>/datasets/`：用户提供的真实测试样本或已生成的可复用数据集，保留 SQL、CSV、JSON 等原生格式。

不在数据源子目录、库或表目录建立第二级索引。已有权威迁移 SQL 保留原位置，由索引引用；新提供
的结构与数据文件按本目录保存，不为集中存放而迁移代码资产。大数据集可引用用户提供的稳定位置，
不为了建库执行数据库导出或全量复制。

## 单索引结构

使用 [索引格式](数据源索引.schema.json)，参考 [填写示例](../templates/数据源索引.json)。示例仅演示
字段关系，不代表任何项目的真实数据，不直接复制其中的源、表或路径。

| 字段 | 用途 |
|---|---|
| `description` | 本项目数据范围说明 |
| `primary_source` | 核心数据源在 `sources` 中的键；仅有外部引用且未确定核心源时为 `null` |
| `sources` | 按稳定名称登记数据源名称、类型和业务用途；优先排列核心源 |
| `tables` | 按稳定表标识登记数据源、库、schema、表名、业务含义、结构文件位置与必要字段语义 |
| `datasets` | 按稳定数据集标识登记所属源、文件、涉及的表、来源说明、适用场景和使用方法 |

对象键仅用于索引内引用，不建立版本或数据库管理平台。源键例如 `core`、`crm`；表键例如
`core.sales.orders`，不同库或 schema 的同名表使用不同键。保留数据库内的真实表名，不用描述代替名称。

路径默认相对于业务项目根目录，便于引用本目录资产和原有迁移文件；外部材料使用用户提供的明确
绝对路径或地址。`ddl` 无可用结构来源时为 `null`，说明当前只知道表用途，不能声称结构已核验。
`key_fields` 只补充影响使用的字段语义，完整类型、主外键、索引和约束由 SQL 表达，不在 JSON 中重复
维护完整 schema。`related_tables` 引用本索引已登记的相关表，不要求收录不相关外部表。

数据集应说明来自用户提供还是生成，覆盖什么场景、如何准备和使用；文件存在不等于已在环境中执行。
生成数据不能标为真实样本；真实测试样本允许作为数据集维护，是否可用由格式、语义和当前场景判断。
读取、执行 SQL 或连接数据库是不同动作；索引和使用说明不授权执行写入或导入。

## 维护与质量

新增、修改或移除资产时，同步唯一索引和受影响引用；表结构变化还需检查关联数据集是否适用。只维护
当前需要的源、表和数据集，不为未涉及的资产创建空文件，不另写一套 Markdown 表结构正文。

回读时依次核对：

1. JSON 能解析且符合字段结构，核心源、表所属源、关联表和数据集涉及表均能在同一索引中定位。
2. 数据源、库、schema、表名共同确定唯一对象；描述能解释业务用途，不只是重复名称。
3. 本地引用存在，SQL 与数据文件格式相符；外部来源不可访问或缺少 DDL 时明确相关边界。
4. 样本语义、覆盖场景与所述使用方法一致；未执行的导入、查询或验证不写成已通过。

JSON Schema 只约束结构，不能证明业务语义、文件存在或数据可执行；后者按实际获得的证据分别说明。
