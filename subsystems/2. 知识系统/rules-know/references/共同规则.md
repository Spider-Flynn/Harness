# 知识资产共同规则

本文是 Build 建设与 Know 增量维护共同遵守的规则。下述写入和回读由调用方完成，读取规则本身不
执行这些动作；项目知识写入目标项目 `.harness/know/`，不写回规则源码。

## 目录与导航

```text
.harness/know/
  README.md
  业务画像.md
  运行模型.md
  功能/<业务模块>/
    README.md
    <功能>.md
  数据源/
    index.json
    <数据源>/schema/<表>.sql
    <数据源>/datasets/<数据集文件>
```

这是按需生长的结构，不是必须生成的目录树。只建设一项功能时，只创建知识总入口、该模块入口和
功能正文。没有已确认知识时不创建空知识入口，不复制空模板表示“已建库”。

总入口说明已有知识的覆盖范围、用途和相对链接，不复制正文。模块入口说明模块职责、边界、功能
导航与必要协作关系，不成为第二份功能正文。知识文件不能只有搜索结果、过程记录或外部链接集合。

业务画像或运行模型变大时，可拆为同名目录内的主题文件，以该目录 `README.md` 为入口；同步修改
总导航和受影响引用，移除已被替代的旧正文，不同时维护文件版与目录版。功能按稳定业务模块分类，
不随每次需求新建一套知识。数据源始终只有一个 `数据源/index.json`，不按源、库、表继续拆索引。

项目已有正式资产时，先确认继续使用还是迁移；在未授权迁移前可由总入口定位原资产，不复制维护
平行正文。源码、迁移脚本等代码资产保留原位置。任务设计、测试、审计等过程材料属于 `.harness/tasks/`
或原有正式载体，是知识来源，不代替本目录中的独立知识内容。

## 共同建设与维护方法

1. 明确本次知识对象和范围；新建与更新遵循相同内容标准，更新只处理受影响的知识和引用。
2. 读取目标现状，比较当前有效知识与本次来源。保持仍有效内容，定位缺失、变更或矛盾，而非整篇追加
   本次聊天或覆盖未涉及的内容。
3. 组织拟写入内容、目标位置、必要来源和未解决问题。已确认事实、已接受但未实现的方案、待确认项
   分开表达；未决内容不得作为默认当前事实被引用。
4. 按当前请求的写入授权与所需门禁应用变化；门禁由主会话依据运行合同处理，本规范不自行增加审计。
   没有未决选择且授权已覆盖时，不为每个文件重复索要确认。
5. 同步总入口、模块导航、数据源索引及直接受影响引用，回读正文和索引，按类型规则核对实际变化。

日常维护可以创建本次所需的最小目录和知识入口；涉及全库分类重组或既有资产迁移时，先返回影响
与建议，由主会话确认范围，不把增量沉淀变为未经请求的全库建设。

## 共同质量要求

- 有持续价值：能支撑后续理解、决策或执行，不逐句转录对话，不把临时调查轨迹当正式知识。
- 有明确边界：说明对象、适用条件及会影响使用的未知项；新项目的目标不伪装成已经运行的系统。
- 有来源：关键结论能回到用户确认、提供的材料或已授权获得的证据。来源已不可访问时保留缺口，
  不为了形式完整补造路径。源码静态关系、测试结果与实际运行结果分别只证明对应范围。
- 能导航和维护：同一内容有一个主位置，相关知识通过引用连接；变更后正文、索引和相邻引用一致。
- 只表达当前所需信息：保留仍影响使用的取舍和候选，不建立知识版本、全量会话日志或额外状态模型。

轻模板提供信息骨架，不强制标题数量、段落顺序或图表；按内容增删，不保留空占位符。已有文档若已
满足质量要求，不因采用模板而重写。机器读取的数据索引遵守固定字段与结构，其质量要求见数据源规则。

可参考 [知识入口轻模板](../templates/知识入口.md)；各类型规则链接自己的模板，均不是业务项目事实。
