# 项目知识沉淀

## 输入与范围

接收 HARNESS 交来的任务过程产物、稳定结果和可回查事实。只提取会影响后续理解、决策或执行的
持久变化；没有这类变化时返回“不沉淀”及简要理由。过程材料是来源，不直接复制为知识正文。

加载只读依赖 `.agents/skills/rules-know/SKILL.md`，按其索引读取共同规则与本次涉及的类型规则。
首次创建与后续更新使用同一规范，不重新执行 Build 的信息源征集或完整问答流程；提取、组织、写入
和回读仍由 Know 完成。依赖缺失或业务含义不清时返回主会话处理，不把未确认推断沉淀成事实。

## 形成知识更新

1. 从稳定结果中定位长期变化，读取目标知识现状，对比需要新增、更正、合并或移除的具体内容。
2. 按共享规范选定主位置，说明拟写入内容、来源、现有内容、差异和会影响使用的未决项。
3. 无知识库时，在 `.harness/know/` 建立本次需要的最小知识与总入口；单项功能按规范建立模块入口，
   数据资产使用唯一数据源索引。不要求四类齐全，不以未执行 Build 阻断首次沉淀。
4. 已有其他位置的正式知识或需要全库重组时，说明受影响资产和建议，由主会话确认范围；不默默迁移
   或建立平行正文。

## 门禁、写入与回读

将候选及仍缺失的裁决、授权交还 HARNESS。是否需要独立审计由当前路线和 Runtime 决定；已有审计
覆盖或不需追加审计时，不自行增加一轮。没有当前所需批准或写入授权时只返回候选。

主会话交回可写结论，或当前请求已经满足所需条件时，执行共享规范中的维护步骤：更新受影响正文
与导航、索引和直接引用，然后回读，按资产类型核对内容与来源。不要重写未受影响部分或再执行一次检索。

返回本次是无变化、候选待处理，还是已写入并回读，列出实际位置、变化和仍未解决的事项。文件能
解析、来源能回查和真实行为验证是不同证据，不混同；不执行 Git、发布或数据库导入等额外动作。
