# 项目知识检索

## 输入与范围

接收当前有效的已确认任务意图。意图缺失或已经失效时停止，不用旧任务推测检索范围。

知识源包括但不限于业务画像、运行模型、功能、数据源、项目规则和其他项目已确认
信息。四类知识是共享规范的资产类型，不是本能力的检索分支或白名单。只读取完成当前意图所需
的最小范围，不建设知识结构，也不触发 `build`。

HARNESS 正常情况下已检查 `.harness/know/README.md` 是否存在；入口缺失仍被调用时，直接返回
“无项目知识入口”，不全库搜索或加载建设规则。入口存在时先读其导航，只沿本次相关链接读取正文。
数据源只读唯一的 `数据源/index.json` 后定位所需表或数据集，不查找每个数据源自己的索引。

## 定位、核验并整合事实

1. 读取项目规则和知识导航，定位候选来源。索引标题、目录名、文件名和搜索命中只提供线索，
   必须读取正文或原始事实后再采用。
2. 核验来源、环境、适用对象、时效和证据边界。材料之间不一致时保留冲突，
   不用较新文件、代码现状或多数来源自动裁决语义事实。
3. 把可使用事实转换为独立信息元，合并语义相同的内容，删除与当前意图无关的背景和原文重复。
4. 信息源缺失、失效、冲突或无权读取时，保留仍有效的信息元，说明受影响范围、任务影响和
   恢复条件，不以推测补齐。

核验知识时可以在任务所需的最小范围内读取代码、配置、DDL 或运行证据，但不因此建立全项目
运行模型、重组知识目录或把一次局部核验扩展成结构性建设。

## 形成任务信息集合

每个信息元只表达一个可独立使用的事实，或一个会影响该事实使用的边界，并包含：

- **内容**：完成当前意图需要的事实或约束；
- **类别与对象**：该事实描述什么知识和对象，不限于四类建设来源；
- **来源与证据**：可回查位置及其实际能证明的范围；
- **适用范围**：项目、环境、条件或时效；
- **状态**：当前事实、候选、冲突、未知或无权；
- **验证边界**：已经核验和仍未核验的部分。

只有状态为当前事实且证据边界满足任务需要的信息元可以作为下游执行依据。候选、冲突、未知和
无权项只说明边界及影响，不能被改写成预期或项目事实。

将信息元组织为下游可直接消费的“任务信息集合”：

```markdown
## 任务信息集合

- 适用任务意图：<当前已确认任务>

### 信息元

1. <内容>
   - 类别与对象：<知识类别及适用对象>
   - 来源与证据：<可回查来源及证明范围>
   - 适用范围：<项目、环境、条件或时效>
   - 状态：<当前事实、候选、冲突、未知或无权>
   - 验证边界：<已核验与未核验范围>

- 集合状态：<是否足以进入下游；真实缺口、影响与恢复条件>
```

只输出整合后的信息元，不输出索引、搜索结果清单或无关来源正文。下游不需要重新读取来源来
替本能力完成事实判断；集合不足时保持相应范围阻断。

## 验证

完成前确认：

1. 每个信息元都与已确认意图直接相关，能够回查来源，并明确适用范围、状态和验证边界。
2. 重复事实已合并；冲突、未知、无权项及其影响没有被隐去。
3. 下游收到的是可直接消费的任务信息集合，而不是索引、搜索结果或来源正文。
4. 没有选择流程、执行任务、调整知识结构或调用 `build`。
