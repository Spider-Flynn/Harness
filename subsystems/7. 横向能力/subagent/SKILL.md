# Sub-agent 编排

## 定位

`subagent` 只负责主干与分支识别、任务分派、上下文交接、结果回收和上一层会话复核，不定义调用场景本身的专业规则。任务由其他 Skill 发起时，阶段规则、事实边界和验收标准仍由调用方负责；用户直接调用时，由主会话先确定共同目标和约束。

Sub-agent 是临时上下文分叉，不是新的用户会话、长期任务所有者或最终交付者。主会话维护用户目标、共同事实、公共决策和阶段推进组成的任务主干，只消费分支在上一层任务粒度上的结论、证据、不确定性和未覆盖项，并负责最终整合和交付。

## 触发与分派门禁

主会话在任务开始和范围变化时主动扫描可分派分支。出现以下任一信号时进入本 Skill 判断，不要等到完成全部节点拆分后才加载：

1. 至少有一个工作包能够封闭返回，主会话只需要其结果而不需要保留完整过程。
2. 一个主干节点还包含多个可独立处理的子节点，且可在上一层粒度汇总。
3. 需要验证、审计、Review、验收或反向质疑，既有实现上下文可能影响判断的独立性。
4. 分支会引入大量与主干后续阶段无关的上下文，隔离后能降低污染、遗忘或压缩成本。

进入判断后，只在能够明确分支目标、必要输入、输出、完成标准和上一层汇合点，且不需要 Sub-agent 自行改变公共事实或验收预期时创建。分派前已知必要输入缺失时不创建；只有执行中发现此前无法识别、且会改变结果的缺口时才返回 `NEEDS_CONTEXT`。分支还必须与其他写入、端口、数据库、外部系统和验证资源相互隔离，并能由上一层会话复核。能够封闭返回只证明分派可行；实际创建前还要确认上下文隔离、判断独立性或并行推进的收益，明确高于初始化、材料重读、结果回收、状态协调和可能返工的成本。

单步即可完成、完全机械且不会增加无关上下文的即时动作，以及强依赖、共享同一最终产物或协调成本高于隔离收益的工作，由当前会话直接处理或改为串行，不为使用 Sub-agent 强行拆分。总 token 降低不是分派的默认目标；允许用可控的额外消耗换取主会话上下文纯度或独立判断质量，但不能让重复读取和重复探索吞掉这些收益。

## 独立验证

凡是需要判断的验证、审计、Review、验收或反向质疑，当其结果将直接指导后续开发、发布或高影响决策时，默认由干净上下文的 Sub-agent 执行。

1. 只向验证者提供待检查产物、权威事实、验收标准、必要环境和结果格式。
2. 不传递实现者的推理过程、期望结论、完整主会话历史或暗示“应当通过”的信息。
3. 验证者返回检查对象、依据、方法、证据、结论、不确定性和未覆盖项，不只返回“通过”或“不通过”。
4. 上一层会话复核检查对象、标准和证据是否支持结论，但不在既有污染上下文中重做同一套独立检查。

无法建立独立上下文时，明确说明独立验证未完成，不把主会话自查等同于独立复核。

## 运行配置选择

主会话在每次分派前，根据节点目标从当前运行时明确暴露的 Sub-agent 类型、模型和推理强度中自主选择运行配置。用户或调用方已给出明确限制时先遵守限制；未指定时按以下顺序决策，不把主会话配置当作默认答案：

1. 根据任务复杂度、上下文规模、歧义、失败影响和结果可验证性确定节点的质量下限。
2. 根据节点实际职责选择能够完整承担该任务的 Sub-agent 类型，再从当前运行时实际支持的候选中，选择能达到质量下限且综合成本最低的模型与推理强度组合，同时考虑 token、时延、并发占用以及失败后返工成本。
3. 将模型能力和推理强度作为两个独立维度判断；只有更深推理能实质降低错误、遗漏或返工风险时，才提高推理强度。
4. 边界清楚、过程简单、容易机械验证且失败影响低的节点，优先使用更轻量的模型或较低推理强度；需要跨来源推理、处理重大歧义、作出高影响决策或难以独立验证的节点，再提升相应配置。
5. 继承主会话配置和使用最强模型与最高推理强度都只是候选，必须经过上述判断，不得无条件套用。

分派时只使用当前工具明确暴露的 Sub-agent 类型、模型、推理强度和覆盖方式。某种类型存在固定配置，或上下文继承方式不允许显式覆盖时，遵守实际运行限制；先按任务正确性和上下文隔离需要选择继承范围，不为更换模型而丢失必要上下文。当运行时不能显式指定所需配置时，使用实际默认配置或重新调整节点划分，不虚构模型名、隐藏能力或已生效的覆盖。

Sub-agent 的任务指令只负责本节点的职责、输入、产出和停止条件，不作为固定模型配置的替代载体。父会话的沙箱与审批策略仍是硬边界，任务指令不能自行扩大权限。只有运行证据能确认实际调用配置时，才宣称使用了相应类型、模型或推理强度。

每次实际创建 Sub-agent 前，先用一句话向用户说明节点、模型、推理强度和选择理由；只有显式选择了特定 Sub-agent 类型时才同时说明类型。多个节点使用相同配置时可以合并。运行时不能显式选择或不能确认实际配置时，明确说明使用实际默认配置，不把候选值写成运行时观测值。该说明只呈现最终选择及关键依据，不展开内部候选比较或完整推理过程。

## 编排方式

### 分层分支

当主干节点还可拆成多个独立子节点时，为该节点指定唯一分支负责者。分支负责者按同样门禁组织内部子节点，复核实际产物并汇总为上一层粒度的单一结果；上一层会话默认不吸收全部子节点过程。

只有分支本身仍具有明确的独立节点，且分层能减少上层上下文和协调成本时才继续向下分派；不为建立完整 Agent 树而增加层级。

### 只读分析

资料、模块或问题可以独立分析时，优先并行：

1. 主会话先确定共同问题、事实来源和输出维度。
2. 每个 Sub-agent 只负责一个明确节点，不重复探索相同范围。
3. 节点返回证据、结论、不确定性和未覆盖项。
4. 主会话统一检查遗漏、重复、冲突和跨节点关系。

只并行启动依赖已经满足且不会争用同一资源的节点，不以占满并发槽位为目标。多个小节点需要重复读取同一批材料、使用相同判断标准且能够由一个负责者按上一层粒度汇总时，合并给一个 Sub-agent，避免为颗粒度本身重复支付上下文和回收成本。

### 共享工作区写入

涉及文件、代码或其他共享状态时，默认优先串行：

1. 每个节点只消费本节点需要的已确认规则。
2. 明确允许修改的文件、禁止范围、测试入口和验证命令。
3. 文件不重叠且测试、端口、数据库、外部系统和其他状态互不污染时，才允许并行。
4. 使用独立 worktree 或等价隔离环境时，可以提高并行度；没有隔离时不得假设写操作安全。
5. 主会话复核每个节点后，统一执行调用场景要求的整体验证。

## 分派内容

每个 Sub-agent 任务只提供必要上下文：

1. 调用场景和节点目标。
2. 必须读取的材料或路径。
3. 当前节点适用的已确认规则。
4. 允许读取、修改或输出的文件范围。
5. 禁止事项、共享状态和不得改变的公共契约。
6. 测试、验证命令和完成标准。
7. 结果返回格式，写入任务还要指定唯一输出路径。

按节点与主会话的关系选择上下文，而不是统一继承或统一清空：

1. 独立验证只传待检查对象、权威事实和验收标准，保持干净上下文；一旦传入实现推理或期望结论，就不得再宣称完全独立。
2. 普通分析或执行分支传递任务摘要、公共决策和必要路径，使其能够正确衔接主干，但不携带无关探索过程。
3. 只有历史无法低成本、低损失地概括，且缺失会实质改变结果时才扩大继承范围；由此增加的 token 和污染风险必须低于重新探索或错误执行的成本。

优先传递文件路径、稳定事实和结构化摘要，不让 Sub-agent 自行大范围探索或读取与节点无关的完整产物。

## 状态与问题回收

Sub-agent 只返回以下状态之一：

- `DONE`：完成标准均已满足且要求的验证通过；返回产物路径、关键证据、验证结果和剩余未验证边界。
- `NEEDS_CONTEXT`：缺少会改变结果的决定、输入或授权；列出缺口、建议答案和不确认的影响。
- `BLOCKED`：环境、已观察状态冲突或验证失败使节点无法在既定范围内完成；说明已验证事实和阻断原因。

任何状态都必须报告已经执行的写入、外部动作及当前状态；没有发生时明确说明没有。

Sub-agent 不直接向用户逐项提问。`NEEDS_CONTEXT` 由主会话累计、去重并按调用场景决定集中询问或停止；影响结果正确性的阻断不得用猜测绕过。返回内容只保留上一层复核所需的结论、关键证据、产物和边界，不回传完整探索轨迹、内部推理或无关工具输出。

主会话回收每批结果后，用实际表现调整后续节点：因上下文不足产生追问或返工时，补充后续同类节点的输入；输出大部分未被使用、重复探索明显或协调等待超过并行收益时，合并或停止后续分支，并相应降低模型、推理强度或并发度。只调整尚未分派的节点，不为记录指标额外制造文档或日志。

## 主会话责任

主会话必须：

1. 分派前检查节点独立性和公共约束。
2. 记录节点状态，避免重复分派。
3. 读取并复核实际产物及其证据，不把 Sub-agent 报告直接当作完成证据，也不在主会话重放整个分支过程。
4. 解决节点之间的重复、冲突和跨节点遗漏。
5. 统一处理用户交互、最终文件和整体验证。
6. 明确未完成节点、未验证项和残余风险。

## 禁止事项

1. 不要让 Sub-agent 自行决定或修改共同事实、公共规则和验收预期。
2. 不要让多个 Sub-agent 同时修改同一最终文件或共享状态。
3. 不要把完整会话历史、完整计划或无关代码全部交给 Sub-agent。
4. 不要跳过主会话复核和调用场景要求的整体验证。
5. 不要把 Sub-agent 当作侧栏独立任务或假设不可见的模型、能力和权限配置。
6. 不要把实现者的结论和完整历史交给独立验证者后，仍宣称其结果没有受到上下文影响。
