# Audit

`audit` 是主会话的审计编排能力。Router 决定当前路线是否需要审计、审计对象和位置；路线到达该节点
后，主会话加载本 Skill 和 `subagent`，创建独立 Audit Subagent，判断其反馈并负责所有修改。Audit
Subagent 只审计，不接管路线、实现、知识写入或人工验收。

## 启动与输入

创建前准备当前可核验的最小输入：

- 审计方向、对象、范围，以及本次审计需要保障的结论；
- 用户当前需求、验收要求和明确不做的事项；
- 当前候选的实际路径、差异或待写入知识，不建立通用候选版本对象；
- 适用的项目规则、权威事实来源及必要调用关系；
- 已执行的测试和其他证据、环境限制、已知未覆盖范围。

信息使用路径或精确引用传递，不复制无关会话历史。创建前已经知道缺少会改变审计结论的输入时，
主会话先补充或询问用户；只有进入只读核验后才暴露的缺口，由 Audit Subagent 返回。

## 创建 Audit Subagent

主会话按 `subagent` 的配置选择与分派规则创建一个只读、干净上下文的节点，名称使用“审计对象 +
审计”。Prompt 必须明确：

1. 只读取上述输入和必要权威来源，不继承实现者的推理、预期结论或完整聊天历史。
2. 不修改候选、代码、知识、规则或外部状态；只有主会话明确允许时才运行不会改变候选和外部系统的
   隔离检查。
3. 按本 Skill 的审计准则核验，返回结论、问题证据和可行建议，不直接修复。
4. 使用 `subagent` 约定的外层状态返回；`DONE` 只表示本轮审计工作完成，不等于候选通过。

## Audit Subagent 的审计准则

1. 先读取当前需求、候选实际差异、适用规则和已有证据，不用摘要替代可以直接核验的来源。
2. 对任务候选核验：
   - 需求和验收是否完整覆盖，所有修改是否服务本次需求；
   - 是否混入无关重构、格式化、依赖变化、顺手修复或其他范围外修改；
   - 存量代码、接口或行为的修改是否必要，是否存在影响更小且同样满足需求的方案；
   - 是否保持未要求改变的兼容行为，并遵守项目既有分层、职责和公共能力；
   - 是否存在无用代码、重复逻辑、过早抽象、不必要依赖或超出需求的防御性实现；
   - 测试类型、真实入口和其他执行证据是否匹配当前风险，未覆盖范围是否如实说明。
3. 对知识候选核对事实来源、现有知识、写入范围，以及是否把推测、过程记录或单次案例升级为长期事实。
4. 只记录能够回到当前来源的问题、影响与可行方向，不要求某个 Skill 修复，也不扩大任务。

## 范围控制

- 本次改动引入、扩大或直接触达的现实风险属于审计范围。
- 已存在的问题只有在会阻断本次需求、使当前实现错误，或被本次改动扩大时，才构成当前阻断项。
- 偶然发现但与本次需求无关的存量问题可以单独记录，不自动扩大修复、回归或审计范围。
- 没有实际触发路径的理论漏洞、无边界安全扫描、与需求无关的代码洁癖和对完美方案的追求，不得
  否定已经足够简单、正确且符合项目习惯的实现。
- 审计保护存量功能不等于禁止修改存量代码；确有必要时重点核验修改理由、影响范围、兼容责任和
  回归证据。

## 输出审计报告

每轮至少返回：

- 审计对象、方向与范围；
- 已核验的权威来源、核验方法、环境边界和执行证据；
- 审计结论：`通过`、`不通过` 或 `无法判断`；
- 问题、证据、影响与可行方案；
- 未覆盖范围、证据缺口和剩余风险。

只有证据充分且未发现阻断问题时才可通过。存在已确认阻断问题时为不通过；证据不足以判断时为无法
判断。后两者不能作为当前候选已经满足需求和验收条件的依据。问题按实际影响排序，并在能够定位时
给出文件和行号；没有问题时也必须说明实际检查范围和未覆盖项。

## 主会话处理与有限复审

一次“主会话提交当前候选或补充事实，Audit Subagent 返回结论”计为一轮，初审是第一轮，同一审计
最多三轮：

1. `通过`：主会话复核审计对象与证据确实对应当前候选，然后返回 HARNESS 继续原路线。
2. `不通过`：主会话逐项判断。认可的问题由主会话一次性修改并补充证据；不认可时只把可核验事实、
   规则或反例返回 Audit Subagent，请其重新判断，不用立场反复争论。
3. `无法判断`：主会话补足能够获得的证据；需要用户决定或外部条件时交回 HARNESS，不由 Audit
   Subagent 猜测。输入补齐后的再次审计计入下一轮。
4. 候选发生修改后，旧结论不再证明新候选通过；还有轮次时由同一 Audit Subagent 只读取当前差异和
   更新证据复审，不建设版本历史或重复传完整上下文。

目标是初审直接通过；需要修改时，通常在第二轮完成一次复审。第三轮返回后必须停止 Agent 间交互：
能够确认的问题仍由主会话处理，但不得声称已经复审通过；仍有实质分歧、证据缺口或风险时如实交给
用户判断。任务目标、范围或路线依据实质变化时结束当前审计，由 HARNESS 重新调用 Router，而不是
借审计对话扩张范围。
