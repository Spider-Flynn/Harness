# Harness Engineering 系统架构

## 一、定位

Harness Engineering 是在人工治理下，以用户意图驱动知识、流程、执行、审计、交付和系统演进的 AI Coding 工程系统，目标是同时提高交付正确性与效率。

## 二、系统边界

系统包含业务项目交付面和 Harness 演进控制面；不假设 AI 能一次理解整个项目，也不把单一文档、代码、测试或模型判断视为绝对真相。

人负责意图确认、业务与例外裁决、风险接受、外部操作授权、高影响知识变更和 Harness 改进批准。

## 三、总体架构

系统由七个职责不同的能力系统组成，并由横向能力共同约束。用户意图决定当前任务需要哪些
能力以及如何组合；预定义流程只提供可复用的候选路径，不构成固定主链。

## 四、能力系统

| 子系统 | 职责 | 核心问题 |
|---|---|---|
| 1. 意图接入系统 | 理解并对齐用户在当前任务中的目标、设计、执行或其他意图。 | 如何准确理解用户真正想做什么，并减少无效确认？ |
| 2. 知识系统 | 按当前意图定位、核验和整合所需事实，并维护长期知识。 | 如何提供完成当前意图所需的可靠事实，并受控沉淀持久变化？ |
| 3. 路由系统 | 需要显式编排时，根据意图和上下文选择预定义流程或组合所需能力。 | 如何用最合适的能力路径服务当前意图，而不是强迫任务适配固定流程？ |
| 4. 执行系统 | 执行选定能力，完成设计、实现、验证或其他任务行动。 | 如何在遵守用户意图和适用约束的前提下自主完成任务？ |
| 5. 审计系统 | 在结果或风险需要独立保障时，以只读、独立上下文审计对象。 | 何时需要审计，以及如何形成可信的独立结论？ |
| 6. 交付系统 | 在需要人工 Review、授权或外部交付时，组织信息并完成受控交付。 | 如何让人有效判断结果、风险和外部操作？ |
| 7. 演进系统 | 复盘 Harness 运行并受控维护系统自身。 | 如何识别真实系统问题并实施可验证、可回退的改进？ |

## 五、运行方式

```text
用户输入 → 对齐当前意图 → 选择所需能力或复用已有流程 → 执行并按反馈调整 → 完成当前意图
```

知识、路由、执行、审计、交付和演进系统只在当前意图、上下文或风险需要时参与，不要求每个
任务依次经过全部系统。意图变化时重新判断所需能力；适用的授权、安全、审计和交付约束不会
因为选择了更短路径而失效。

系统能力的最小 Skill 集、简短命名和非 Skill 载体以
[Skill 能力设计](./实施方案/Skill%20能力设计.md)为准；预定义流程、跨系统编排和演进分别由
[`flows/流程路由.md`](../flows/流程路由.md)、
[`runtime/系统流程.md`](../runtime/系统流程.md)、
[`任务交付闭环`](../runtime/整体编排/任务交付闭环.md)和
[`系统演进闭环`](../runtime/整体编排/系统演进闭环.md)维护，并应遵守本架构的意图驱动原则。

## 六、横向能力

### 6.1 审计机制

按当前意图和风险为任务输入、稳定产物和知识沉淀提供规则检查、确定性验证、独立语义审计与人工门禁。

### 6.2 会话与 Agent 编排

Skill 定义单项能力怎么做，专用 Agent 定义固定 Prompt、职责和权限，Subagent 提供运行时临时上下文分叉；编排机制负责选择主会话、分支会话或独立会话并完成交接与回收。

### 6.3 稳定产物共性规则

跨系统文档和稳定产物必须说明来源、适用任务、当前有效性、变更关系和验证边界，并支持追溯与失效判断。

### 6.4 运行证据契约

参与当前任务的系统产生并交接复盘所需的最小运行证据；演进系统负责解释证据，并在人工批准后实施、验证和记录改进。

## 七、额外能力

额外能力按用户意图、输入来源或当前问题独立触发；其结果成为当前任务可用输入，不因此进入
固定系统链路或获得其他操作授权。

## 八、架构原则

1. **意图驱动**：用户意图决定任务需要的能力及其组合，预定义流程只作为候选路径。
2. **意图与事实分离**：用户决定想要什么，项目证据说明当前是什么。
3. **索引与交接分离**：知识系统用索引定位并核验来源，任务只消费带证据边界的信息。
4. **能力与载体分离**：Skill 定义怎么做，专用 Agent 定义固定执行角色，Subagent 定义临时分叉。
5. **路由、执行、审计与批准分离**：任何一方不自行决定不属于自身职责的事项。
6. **知识沉淀归知识系统**：交付负责触发，审计负责门禁，知识系统负责判断与写入。
7. **风险驱动**：上下文、能力组合、产物和审计强度服从任务风险。
8. **真实证据优先**：关键真实链路不能被 Mock、编译或模型判断代替。
9. **可追溯、可回退**：长期变化必须有来源、验证和撤销边界。
