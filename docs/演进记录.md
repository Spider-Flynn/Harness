# Harness 演进记录

> 用途：记录经用户确认采纳的 Harness 改进候选、实施修改的载体与验证历史事实。
> 规则：未经过实际复盘证实、用户未拍板采纳或仅为设计探讨的内容不在此记录。

## 记录规范

每次演进记录按以下结构追加：

```markdown
### [YYYY-MM-DD] 改进项简述

- **任务背景**：关联的业务项目与任务目录（如 `.harness/tasks/YYYYMMDD-简名/`）
- **问题证据**：实际观察到的系统偏差、摩擦或失败点（结合 retro.md 与 events.jsonl）
- **作用机制**：导致问题的 Harness 机制、能力或规则缺陷
- **修改载体**：实际修改的 Skill、框架规则、运行时合同或脚本（附带文件链接）
- **验证方式**：执行的场景测试或复核验证结果
- **状态**：已验证 / 观察中
```
