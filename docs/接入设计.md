# 项目接入工具设计

本文面向接入工具维护者，记录当前模块职责、命令对应关系与存储边界。用户使用说明见
[README](../README.md)，整体框架合同见 [系统设计](./系统设计.md)，后续事项见 [TODO](../TODO.md)。

## 对话与执行入口

AI 读取 `cmd/<命令>.md` 完成必要交互、组织参数和解释结果，再调用
`python3 scripts/harness.py <命令> ...`。用户手动运行 CLI 时进入相同实现。

`scripts/harness.py` 仅调用 `harness_cli.cli.main()`；`cli.py` 负责参数解析、命令分派、错误展示和
退出码。它将已确定的参数交给对应命令模块的 `run()`，各命令模块不作为独立脚本运行。

| AI 交互指引 | CLI 命令 | Python 命令模块（位于 `scripts/harness_cli/commands/`） |
|---|---|---|
| `cmd/init.md` | `init` | `init.py`：首次绑定、冲突检查与失败恢复 |
| `cmd/relink.md` | `relink` | `relink.py`：复用原选择，重建链接、规则片段与记录 |
| `cmd/doctor.md` | `doctor` | `doctor.py`：检查目标绑定并返回错误或提示，不修复 |
| `cmd/remove.md` | `remove` | `remove.py`：解除受管绑定并保留项目原有内容 |
| `cmd/list.md` | `list` | `list_projects.py`：展示本仓库记录的项目索引 |

`cmd/` 不是第二套脚本实现，也不进入业务 Runtime。AI 负责灵活判断与用户交互，Python 负责
确定性检查和实际文件操作。直接使用 CLI 时，系统与规则入口的必要交互由对应公共模块完成。

## 公共模块

以下模块均位于 `scripts/harness_cli/`：

| 模块 | 唯一职责 |
|---|---|
| `catalog.py` | 发现和校验领域系统、发现 Skills、选择系统及投影能力 |
| `binding.py` | 构造、读取和校验目标项目绑定清单及其 Runtime、Skill、共享资源链接，不管理本仓库索引 |
| `rules.py` | 选择 AGENTS/CLAUDE 入口，维护受管片段，保存和恢复规则内容 |
| `git_hooks.py` | 按领域策略规划、安装、检查和解除 Git Hook，并保护接入前的原 Hook |
| `storage.py` | 管理本仓库项目索引、操作锁和损坏索引备份，对外提供带锁的索引读写 |
| `filesystem.py` | 路径检查、原子写入、文件锁与软链接操作，不决定命令流程 |
| `paths.py` | 定位 Harness 源目录，定义目标项目受管路径 |
| `errors.py` | 定义供 CLI 统一展示的接入错误 |

命令模块组合公共能力，互不调用；公共模块不反向调用命令或 CLI。各命令仍负责自身的操作顺序和
可捕获异常恢复，不引入通用工作流引擎。分模块不改变原有命令参数、清单格式与受管范围。

## 数据位置与所有权

Harness 仓库的本地辅助数据按需生成，整个 `data/` 由 Git 忽略：

```text
data/
  projects.json        已绑定项目索引
  locks/               项目操作锁、索引锁
  backups/             损坏索引的隔离备份
```

位置从 Harness 源文件推导，与命令执行目录无关；不使用用户主目录，也不随源码提交和分发。业务
项目的 `.harness/manifest.json` 才是该项目的绑定事实，保存原系统、规则入口、可选能力、受管链接及
Git Hook 记录。
`data/projects.json` 只服务于列表和项目定位，不复制业务代码、知识或过程产物。

能力源码从 `subsystems/<职责域>/<skill>/SKILL.md` 发现，只有具有该入口的目录才作为 Skill。
`systems/` 只存领域 Manifest；当前知识规则封装为 `subsystems/2. 知识系统/rules-know/`，随默认
Skills 投影到 `.agents/skills/rules-know/`，供 Build 与 Know 沉淀读取，不单独投影知识资源。

领域清单可选声明 `resources`。接入时，资源目录以 `.harness/resources/<名称>` 软链接投影，项目
清单以 `resource_links` 记录目标相对路径及绝对源码。当前软件工程清单不再声明知识资源，但仍兼容
旧绑定记录：`doctor` 会提示缺少 `rules-know` 或保留旧资源；`relink` 添加规则 Skill 并移除原
`.harness/resources/knowledge` 受管链接。缺少资源字段时按空资源读取，无需变更清单版本。`.harness/know`
与 `.harness/tasks` 属于目标项目的知识和持久化任务产物，不是受管链接，解绑不会删除。首次接入按
具体受管路径冲突检查，因此可保留这两个目录及其他不冲突的用户内容。Runtime、Skills 和资源目标
本身使用受管软链接；父目录为软链接或目标被普通文件、目录占用时仍拒绝写入，避免越过项目目录或覆盖
用户文件。

索引丢失或损坏不阻断目标项目的检查、修复与解绑；`relink` 可按项目清单重建当前项目索引，内容损坏
的普通索引先移入 `backups/`。索引路径被非普通文件占用时返回明确提示，不自动移走用户内容。

Harness 源目录移动后，从新位置运行 `relink --project <原项目>` 修复 Runtime、Skills 和资源的绝对
软链接。仅运行 `list` 不证明目标绑定完整，仍需 `doctor` 检查。

领域 Manifest 可选声明 `git_hooks`；当前支持 `pre-commit` 与 `prepare-commit-msg` 的
`protected_branches`。软件工程实例接入普通 Git 工作树时同时安装两者，前者尽早拦截，后者确保
`--no-verify` 不能跳过分支门禁。原路径已有文件或符号链接时原样移动为
`<hook>.harness-original`，包装 Hook 在非受保护分支继续执行它；解绑恢复原路径。绑定清单记录受保护
分支，以及原 Hook 的文件摘要与权限或符号链接目标；`relink` 同步策略，`doctor` 检查受管内容、
执行位和备份身份，`remove` 只恢复与记录一致的原 Hook，操作失败则按快照恢复相关路径。符号链接
`.git` 可能指向其他仓库，linked worktree 的 Hook 目录可能由同仓库多个工作树共享，`core.hooksPath`
也可能指向共享或自定义位置，因此当前均拒绝自动接管；显式非 Git 绑定不生成 Hook 记录。
Git Hook 身份记录从绑定清单 version 3 开始；原 version 2 清单没有 Hook 字段，`relink` 会在补齐双
Hook 时升级清单。发现无清单对应的旧 Harness Hook 标记时拒绝接管，避免将包装 Hook 误作业务原件。

## 验证边界

接入脚本的临时目录冒烟只覆盖确定性文件操作，不证明 AI 会正确加载对话指引，也不证明宿主在任务中
持续遵守 Runtime。真实接入会话与业务主链仍待后续验证；当前不提供会话前 Runtime Hook 或 TUI，
也不执行 Build 或演进流程。Git 提交 Hook 只验证分支门禁，不证明 Runtime 已被宿主加载。
工具处理可捕获异常的恢复，强制终止进程后的半完成绑定恢复仍列在 TODO，不能宣称已覆盖。
