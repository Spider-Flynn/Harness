# 3. 路由系统

## 一、职责与产出

根据上游输入选择工作流程，产出“选定工作流程”及其 Skill 索引。

本系统只维护流程路由信息并完成路由判断，不执行流程、定义 Skill 内部行为或管理任务状态。

## 二、核心问题

1. 如何向路由引擎提供可选工作流程及对应 Skill 信息。
2. 如何根据初始任务或反馈请求选择工作流程。

## 三、解决方案

### 3.1 流程路由信息

用文件集中记录可选工作流程及对应 Skill 入口，为路由引擎界定选择范围；具体文件结构在落地阶段设计。

### 3.2 路由引擎

用 `router` 定义判断规则；需要固定 Prompt、职责和权限时，可配置“路由 Agent”作为专用执行角色。Skill 规定如何判断，Agent 承载固定角色，会话与 Agent 编排决定在哪种上下文运行；三者不是替代关系。

路由引擎接收：

- 初始请求：已确认任务意图与由可追溯信息元组成的任务信息集合；
- 反馈请求：问题、审计或人工反馈，以及仍有效的意图、产物和约束。

路由引擎只选择工作流程，不决定产物失效、任务恢复或终止。

意图接入、独立知识建设、审计、人工交付和 Harness 演进属于固定阶段、显式能力或独立控制面，不作为业务执行流程交给
`router` 选择。

## 四、协作关系

```text
初始请求或反馈请求 + 流程路由信息 → 路由引擎
→ 选定工作流程 + Skill 索引 → 执行系统
```
