# 6. 交付系统

## 一、职责与产出

接收 Harness 编排提供的交付审查包，组织人完成最终 Review、验收与风险接受，并在明确授权范围内完成或核验外部交付，产出人工审查结果、反馈请求、人工修改事实或交付结果。

本系统只执行交付规则，不判断何时进入交付，也不决定候选失效、反馈回流、重新审计或后续系统；最终判断、风险接受和外部授权始终由人完成。

## 二、核心问题

1. 如何让人以最小信息负担 Review 上游全流程产出。
2. 如何区分可以在 Review 内解释的疑问和需要改变候选、验收或证据的反馈。
3. 如何在明确授权范围内执行或核验外部操作，并形成真实交付回执。

## 三、解决方案

### 3.1 实施载体

由主会话加载 `cr`，组织审查信息与人工交互，并在明确授权后调用对应工具完成或核验外部交付。

### 3.2 人工 Review

审查信息包含已确认任务意图与验收、任务信息集合、选定流程、候选对象及版本、稳定产物、信息源与已核验事实、候选代码及差异、执行证据、适用于同一版本的审计报告、未覆盖范围与剩余风险，以及计划交付操作的目标和范围；不默认包含全量对话和临时探索。

人检查意图是否满足、产物与事实是否一致、风险是否可接受，以及交付目标和范围是否正确。

理解性疑问只依据现有审查信息解释并继续 Review；需要新增调查、验证或修改时形成反馈请求。人直接修改候选时，本系统只记录修改对象、版本、内容和已知影响。

### 3.3 受控交付

外部操作必须获得覆盖操作、目标和范围的明确授权，并符合当前项目规则。执行前核对授权、审查通过的候选版本和计划交付范围；执行后以实际工具或外部系统结果形成逐项回执。

授权不代表成功。部分成功或失败时记录当前外部状态，不自动重试、回退或扩大操作；无需外部操作时明确记录该事实。

### 3.4 输出

- 人工审查结果：候选对象与版本、人的接受或拒绝、风险接受、授权和仍未知事项。
- 反馈请求：候选对象与版本、反馈原文、对象与范围、已确认事实、不确定项、人工决定和授权状态。
- 人工修改事实：修改前后的对象与版本、修改内容、已知影响、人工决定和授权状态。
- 交付结果：候选对象与版本、人工接受与风险接受、最终稳定产物与事实来源、授权范围、实际回执、成功或失败结论和未完成事项。

## 四、协作关系

```text
Harness 编排 → 交付审查包 → cr ↔ 人工 Review
                              → 人工审查结果 / 反馈请求 / 人工修改事实 / 交付结果 → Harness 编排
```
