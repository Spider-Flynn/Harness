# Harness Engineering 横向能力设计

## 一、定位

横向能力是多个主流程系统共同使用的控制机制，不是独立时序节点，也不替代任何子系统职责。

## 二、审计机制

审计机制为各阶段提供规则检查、确定性验证、独立语义审计和人工门禁；被审计对象所属系统负责处理结果。

审计系统是交付前的正式审计节点，知识系统可在沉淀前调用同一机制。

## 三、会话与 Agent 编排

- **Skill** 定义按什么流程执行、何时交互以及需要什么产物。
- **专用 Agent** 是预配置固定 Prompt、职责和权限的执行角色。
- **Subagent** 是运行时创建的临时上下文分叉，可执行通用任务或加载专用 Agent，但本身不代表固定角色或独立审计。
- **主会话、分支会话和独立会话** 定义上下文继承与隔离方式。

编排机制根据交互需求、上下文继承、隔离、并行收益和权限要求选择运行形态，负责交接、回收和汇总；路由系统只选择工作流程。

主会话保留任务主干和人工交互；需要继承上游上下文时使用分支会话；独立审计使用不继承产出者推理的干净上下文。节点间只交接稳定产物、必要证据和索引。

会话与 Agent 编排的公共边界属于 runtime 和项目规则；Harness 同时在
`skills/8. 横向能力/subagent/` 维护隔离副本，统一分支判断、上下文交接、独立验证和结果回收行为。`subagent` 可被任何系统按需加载，不构成独立时序节点。

## 四、稳定产物共性规则

跨系统文档和稳定产物必须说明来源、适用任务、当前有效性、变更关系和验证边界，并支持追溯与失效判断。

本能力只定义共同交接要求；知识分类与沉淀归知识系统，具体产物类型归工作流程中的 Skill。

## 五、运行证据契约

各系统只保留复盘所需的最小运行证据，包括阶段、路由、信息源使用、能力调用、人工介入、耗时、Token、返工、审计和交付结果。

本能力定义证据的产生与交接；演进系统负责解释证据并管理 Harness 改进。

## 六、落地归属

- 用户级 `AGENTS.md`：稳定、跨项目的共同边界。
- 项目级 `AGENTS.md`：项目专属规则与硬约束。
- Skill：工作流程、交互条件和产物要求。
- Agent 配置：固定角色的 Prompt、职责和权限。
- 脚本、测试、Hook 或配置：可确定执行的检查与硬门禁。

因此横向能力是系统分类，不为目录完整性强行创建 Skill 或空目录。
