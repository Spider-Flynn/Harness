# 5. 审计系统

## 一、职责与产出

接收 Harness 编排提供的交付候选或知识候选审计包，进行只读、独立、基于证据的审计，产出“审计报告”和反馈事实。

本系统只执行审计规则，不判断何时触发审计，也不负责后续编排、修复、授权或写入。

## 二、核心问题

1. 审计需要读取哪些对象、契约、信息源和执行证据。
2. 如何保持审计上下文独立且权限只读，避免继承产出者偏差或直接修复。
3. 如何形成足以支持上游判断的审计报告。

## 三、解决方案

### 3.1 审计输入

审计包由 Harness 编排确定并交付，包含审计方向、目标与范围、被审计对象及版本、已确认任务意图与验收、适用规则、允许读取的权威信息源及核验方式、执行证据、环境限制和已知未覆盖范围。

交付审计还读取任务信息集合、选定流程、稳定产物、候选代码及其差异；知识审计还读取最终稳定产物、事实来源、现有知识、待写入知识和目标写入位置。

### 3.2 实施载体

- 用 `audit` 定义审计规则、证据要求和报告结构。
- `agents/openai.yaml` 只维护 Skill 的界面元数据和默认提示，不代表已经具备平台级只读权限。
- 由会话与 Agent 编排提供干净上下文和只读运行边界；Subagent 只是可选的临时分叉形式，不天然保证独立。
- 只有审计包提供可核验的只读或隔离执行边界时，才调用测试、编译、静态检查、真实链路验证或结构检查等确定性工具；否则将对应验证列为未覆盖范围。

### 3.3 核心规则

- 审计方独立读取原始权威信息源，不把产出者结论当作证据。
- 审计只读且不得修复；发现问题只提供证据、影响和可行方案。
- 证据足够且未发现阻断问题时通过；发现问题或证据不足时均不得通过。
- 报告必须说明对象、范围、方向、核验方法与环境边界、证据、结论、问题、方案、未覆盖范围和剩余风险。

`audit` 是审计方法、输入和报告合同的唯一能力入口。

## 四、协作关系

```text
交付候选审计包 ─┐
                  ├→ audit → 审计报告 + 反馈事实 → Harness 编排
知识候选审计包 ─┘
```
