# Audit

`audit` 接收已经由 Harness 编排确定的审计包，在独立上下文、只读权限下核验候选是否有足够证据支持，并返回审计报告与反馈事实。

## 接收审计包

审计包必须标明审计方向、目标与范围、对象及版本、已确认任务意图和验收要求、适用规则、允许读取的权威信息源及核验方式、执行证据、环境限制和已知未覆盖范围。

- 交付候选还应包含任务信息集合、选定流程、稳定产物、候选代码及差异、验证结果和计划交付范围。
- 知识候选还应包含最终稳定产物、待写入知识、事实来源、现有知识和目标写入位置。

关键信息缺失、对象版本无法确认或证据不可核验时，停止并判定不通过；只在报告中说明缺口，不补造证据。

## 独立审计

1. 在不继承产出者推理或结论的上下文中，先读取审计包和原始权威信息源。
2. 根据审计方向、对象、适用规则和证据边界执行必要的只读核验：结构、差异、静态检查、编译、测试或真实链路证据。只有审计包提供了可核验的只读或隔离执行边界时才运行验证命令；需要产生临时产物的命令只能在指定隔离环境中执行，不得修改被审计对象、候选知识或外部状态。无法确认执行边界时，将对应验证列为未覆盖范围。
3. 分别核对对象与意图、验收、适用规则和证据。交付候选还核对任务信息集合、选定流程、变更与执行结果；知识候选还核对事实来源、现有知识和写入范围。
4. 发现问题时只记录可复核证据、影响和可行方案；不得编辑、修复、写入或要求某个执行 Skill 处理。

## 输出审计报告

报告至少包含：

- 审计对象、版本、方向与范围；
- 已核验的权威来源、核验方法、环境边界和执行证据；
- 审计结论：`通过` 或 `不通过`；
- 问题、证据、影响与可行方案；
- 未覆盖范围、证据缺口和剩余风险。

只有证据充分且未发现阻断问题时才可通过。发现问题或证据不足均为不通过。

不通过时，在审计报告中提供可供上游处理的反馈事实；报告返回后审计任务结束。
