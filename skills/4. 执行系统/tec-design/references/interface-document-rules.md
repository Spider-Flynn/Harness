# Markdown 接口文档规则

仅在产出供人工阅读和评审的 Markdown 接口契约时使用本规则。

## 契约内容

1. 根据接口实际内容自然组织，不强制标题数量、表格结构或章节顺序。
2. 每个接口完整表达用途、请求方法、请求路径、入参、出参、请求示例和响应示例；鉴权、错误、幂等、分页或兼容约束只在接口实际需要时补充。
3. 字段只写已确认的类型、必填性、含义和必要约束。示例必须与字段定义一致，只具体化已确认的业务语义。
4. 示例不得用看似真实的值补齐未确认规则，也不得包含真实凭据、个人信息或其他敏感数据。
5. 无入参或无响应体时直接说明，不为结构完整保留空标题、空表格或占位内容。

## 一致性与边界

1. Markdown 文档是接口契约的人类可读表达，不替代技术设计中的功能规则、核心数据、数据源规则和具体流程。
2. 同时产出 Swagger JSON 时，两种表达必须来自同一批已确认接口事实，并保持方法、路径、参数、字段、约束、响应和错误边界一致。
3. 改造现有接口时，以已确认的原契约和兼容责任为基础，只呈现当前有效结果，不记录字段变更过程。
4. 文件命名和存放位置服从当前任务与目标项目规则。文档完成只证明接口契约已形成，不证明接口已经实现、部署或通过验证。
