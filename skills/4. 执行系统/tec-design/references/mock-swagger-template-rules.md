# Mock Swagger JSON 模板规则

仅在使用 `assets/mock-swagger-template.json` 产出机器可读的 Swagger 2.0 接口契约时使用本规则。

## JSON 产出

1. 使用已确认的接口事实生成合法的 Swagger 2.0 JSON，不添加注释或非规范字段。
2. `info.title` 填模块或功能名称；`tags` 与各接口操作下的 `tags` 使用一致的接口分类。
3. 需要鉴权时使用 `securityDefinitions` 和接口级或全局 `security` 表达；不要把
   `Authorization` 声明为普通 header 参数。鉴权类型、名称和适用接口按真实契约调整。
4. 新增接口按已确认的请求、响应、字段含义、约束和错误边界生成。
5. 改造现有接口时，以已确认的原契约和兼容责任为基础，只写当前有效的保留、新增、修改和删除结果，不用模板示例覆盖原契约。
6. 示例值只具体化已确认规则，不包含真实凭据、个人信息或其他敏感数据。
7. 文件命名和存放位置服从当前任务与目标项目规则。

JSON 文件完成只证明机器可读契约已形成，不证明接口已经实现、部署、导入外部平台或通过验证。
