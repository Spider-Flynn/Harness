# Coding

## 定位

`coding` 负责按照已经确认的行为和范围修改生产代码。它把技术方案、契约、根因或行为基线
作为约束，不在编码过程中重新定义这些事实，也不负责流程编排。

本 Skill 形成生产代码候选以及代码层面的检查证据。编译或静态检查通过只证明相应代码检查
成立，不证明业务行为、单元测试或真实 HTTP 链路已经验证。

## 执行前提

开始前确认：

1. 目标行为、修改范围和不能改变的行为已经明确。
2. 相关入口、接口、数据结构、依赖和现有实现已经定位。
3. 当前文件及已有工作区修改已经重新读取，其意图能够保留。
4. 目标项目和语言的现行规则，以及适用于受影响模块的编译或静态检查方式已经识别。

不同修改类型还必须满足对应条件：

- 新功能或行为调整：预期的用户可观察行为和兼容边界已经确认。
- 缺陷修复：错误行为、正确预期和根因均有证据支持；只修改根因对应范围。
- 重构：修改前行为基线和必须保持的契约已经确认；不借重构改变外部行为。

信息缺失只有在会实质改变实现时才构成阻塞。遇到阻塞时说明已知事实、缺口、影响和恢复
条件，不通过猜测补齐契约、根因或预期。

## 编码执行

1. 读取距离目标代码最近的项目规则、当前源码和直接依赖，以当前内容为事实基线。
2. 沿真实入口和调用关系确定最小影响面，列明需要修改和必须保持不变的文件、接口与数据。
3. 使用与项目现有分层、命名、错误处理和依赖方式一致的最小实现完成目标行为。
4. 重新读取修改后的文件并检查实际差异，确认没有覆盖用户修改或混入无关变化。
5. 运行项目已有且适用于受影响模块的编译、类型检查、lint 或其他静态检查，记录实际命令、
   结果和未覆盖范围。

本 Skill 不选择技术设计、测试设计、TDD、单元测试或 HTTP 集测，不编写或修改测试代码，
也不决定接下来应执行哪个 Skill。测试或行为验收未由其他能力实际完成时，将其保留为未验证
风险。

## 通用编码规则

- 项目规则和语言惯例优先；没有明确约定时，选择简单、局部且容易理解的实现。
- 复用现有分层、对象、公共能力和错误语义，不为减少少量代码引入新的抽象或依赖。
- 只修改实现目标直接需要的内容，不顺手重构、统一格式、升级依赖或处理无关问题。
- 把当前文件和已有修改视为有意基线；来源不明的内容不删除、不回退、不整文件重写。
- 外部输入在进入业务边界时校验必填、长度、格式、枚举、引用对象和存储约束，失败语义与
  项目现有契约一致。
- 除非已确认要改变契约，否则保持接口入参、返回结构、字段语义、序列化方式、错误码和默认
  行为兼容。
- 异常处理保留可诊断信息，不吞掉需要上层感知的失败，也不把内部实现或敏感信息暴露给
  外部调用者。
- 处理凭证、密钥、token、个人信息和其他敏感数据时遵守最小暴露原则，不在代码、日志或
  错误信息中明文泄露。

## 条件工程规则

以下规则只在修改涉及对应机制时适用：

- **日志**：关键业务日志包含能够关联请求或业务对象的标识；外部调用记录必要的结果和耗时，
  对参数与响应进行脱敏，避免无界大对象和重复噪声。
- **事务**：事务边界只覆盖需要原子性的本地状态变化，避免把慢查询、远程调用或无关计算放入
  大事务；异常必须按既定回滚语义传播或转换。
- **幂等**：可重试写操作和状态变化使用稳定业务唯一键，明确重复请求、并发更新和超时后状态
  不确定时的处理方式，不能把超时直接等同于最终失败。
- **远程调用**：使用项目统一客户端和超时配置，保留明确的失败语义；避免循环逐条调用，能够
  批量处理时优先使用既有批量能力，并评估重试造成的重复副作用。
- **Redis**：key、序列化和命名空间遵循项目约定；临时数据设置符合业务生命周期的过期时间，
  避免对可能很大的集合执行无界全量读取。

## 命名与注释

- 命名准确表达业务含义，并在同一概念上保持术语一致；作用域越大，名称越完整。
- 注释说明代码本身难以表达的业务职责、约束来源、异常语义和非显然取舍，不复述语法或逐行
  翻译代码。
- 修改行为时同步修正失效注释，保留仍然正确的说明；项目没有语言约定时，业务注释默认使用
  中文，代码标识符和通用技术术语保持原样。
- 已有主流程使用步骤编号时，修改后同步维护编号；不为简单转发、字段访问或名称已经完整表达
  行为的方法强行增加注释。

## Java 条件规则

仅在 Java 任务中应用以下规则，并以项目现有约定为先：

- 根据仓库构建配置、toolchain 和编译目标使用相应 JDK，不假设宿主机的默认 Java 版本或固定
  管理工具。
- 公共 API 和承担独立业务规则、非显然转换或失败语义的方法使用简洁 Javadoc；文件头只在
  项目已有明确规范时添加，并沿用现有格式。
- 使用 Spring 事务时检查代理边界、方法可见性、同类内部调用、异常捕获和回滚异常类型，避免
  `@Transactional` 实际未生效。
- 对 DTO、实体和持久化字段的校验同时考虑 Java 类型、序列化契约及数据库长度和空值约束。

## 完成与输出

完成前确认修改只覆盖既定范围，契约、兼容性、安全、性能和稳定性风险已经复核；适用的编译
或静态检查已实际运行。检查无法执行或失败时，保留真实状态，不把代码候选描述为已经验证。

输出包括：

1. 修改的生产代码及其范围。
2. 实际运行的编译或静态检查命令、结果和证据边界。
3. 未完成的行为验证、环境限制、兼容性影响和残余风险。
