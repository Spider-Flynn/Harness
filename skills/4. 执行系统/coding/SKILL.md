# Coding

## 定位

`coding` 是编码过程的必加载规则，不是独立的路线规划或验证阶段。Router 决定当前需求是否
需要修改生产代码；一旦需要，HARNESS 在编码时加载本 Skill，将其中的个性化习惯和本机环境约束
应用到实际修改。

目标行为、修改范围、设计、根因、测试策略和审计门禁由上游需求、Router 和对应能力确定。本 Skill
不重新判断这些事项，也不要求编译、lint、测试或其他代码级自检。

## 规则优先级

1. 业务项目明确规则、当前契约和用户对本次任务的要求优先。
2. 当前代码的分层、命名和已有写法是局部事实基线；不以个人习惯覆盖项目已经稳定采用的约定。
3. 没有更具体约束时，应用本 Skill 的个性化编码习惯。

## 个性化编码习惯

- 项目规则和语言惯例优先；没有明确约定时，选择简单、局部且容易理解的实现。
- 复用现有分层、对象、公共能力和错误语义，不为减少少量代码引入新的抽象或依赖。
- 只修改实现目标直接需要的内容，不顺手重构、统一格式、升级依赖或处理无关问题。
- 把当前文件和已有修改视为有意基线；来源不明的内容不删除、不回退、不整文件重写。
- 外部输入在进入业务边界时校验必填、长度、格式、枚举、引用对象和存储约束，失败语义与
  项目现有契约一致。
- 除非已确认要改变契约，否则保持接口入参、返回结构、字段语义、序列化方式、错误码和默认
  行为兼容。
- 异常处理保留可诊断信息，不吞掉需要上层感知的失败，也不把内部实现或敏感信息暴露给
  外部调用者。
- 处理凭证、密钥、token、个人信息和其他敏感数据时遵守最小暴露原则，不在代码、日志或
  错误信息中明文泄露。

## 条件工程规则

以下规则只在修改涉及对应机制时适用：

- **日志**：关键业务日志包含能够关联请求或业务对象的标识；外部调用记录必要的结果和耗时，
  对参数与响应进行脱敏，避免无界大对象和重复噪声。
- **事务**：事务边界只覆盖需要原子性的本地状态变化，避免把慢查询、远程调用或无关计算放入
  大事务；异常必须按既定回滚语义传播或转换。
- **幂等**：可重试写操作和状态变化使用稳定业务唯一键，明确重复请求、并发更新和超时后状态
  不确定时的处理方式，不能把超时直接等同于最终失败。
- **远程调用**：使用项目统一客户端和超时配置，保留明确的失败语义；避免循环逐条调用，能够
  批量处理时优先使用既有批量能力，并评估重试造成的重复副作用。
- **Redis**：key、序列化和命名空间遵循项目约定；临时数据设置符合业务生命周期的过期时间，
  避免对可能很大的集合执行无界全量读取。

## 命名与注释

- 命名准确表达业务含义，并在同一概念上保持术语一致；作用域越大，名称越完整。
- 注释说明代码本身难以表达的业务职责、约束来源、异常语义和非显然取舍，不复述语法或逐行
  翻译代码。
- 修改行为时同步修正失效注释，保留仍然正确的说明；项目没有语言约定时，业务注释默认使用
  中文，代码标识符和通用技术术语保持原样。
- 已有主流程使用步骤编号时，修改后同步维护编号；不为简单转发、字段访问或名称已经完整表达
  行为的方法强行增加注释。

## Java 条件规则

仅在 Java 任务中应用以下规则，并以项目现有约定为先：

- 根据仓库构建配置、toolchain 和编译目标使用相应 JDK，不假设宿主机的默认 Java 版本或固定
  管理工具。
- 公共 API 和承担独立业务规则、非显然转换或失败语义的方法使用简洁 Javadoc；文件头只在
  项目已有明确规范时添加，并沿用现有格式。
- 使用 Spring 事务时检查代理边界、方法可见性、同类内部调用、异常捕获和回滚异常类型，避免
  `@Transactional` 实际未生效。
- 对 DTO、实体和持久化字段的校验同时考虑 Java 类型、序列化契约及数据库长度和空值约束。

## 本机环境边界

- 先读取业务项目保存的语言版本、构建工具、启动方式和环境配置；这些项目事实不复制进本 Skill。
- 本 Skill 可以维护个人机器上稳定复用的环境使用习惯，但不得写入凭据、私有业务地址或只服务单次
  任务的临时路径。
- 环境缺口会影响编码时，只返回缺少的环境事实；是否补充事实、调整路线或执行检查由 HARNESS 和
  对应能力决定。
