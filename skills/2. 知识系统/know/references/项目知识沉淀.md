# 项目知识沉淀

## 输入与范围

接收任务过程产物、最终稳定结果、实际验证和可回查事实，只处理未来任务仍需要依赖的持久变化。
过程产物是提取知识的事实来源，不直接作为知识内容；沉淀结果按项目已经建立的业务知识、项目核心
运行模型、功能知识、数据知识等独立知识结构维护。

临时过程、尚未形成稳定结果的内容、仅服务当前任务的记录和未经确认的推测不沉淀。

本能力沿用项目现有知识结构。没有可用位置或需要调整整体结构时只保留缺口，不自行设计结构，
也不调用 `build`。

## 判断并形成知识候选

1. 判断变化是否会改变后续理解、决策或执行；没有持久变化时输出“不沉淀”。
2. 从过程产物、稳定结果和可回查事实中提取长期有效内容，按项目现有知识结构确定知识类别和目标位置。
3. 形成知识候选，包含待写入知识、事实来源、现有知识、目标位置、适用范围、差异、冲突与
   验证边界。
4. 将候选连同审计所需的现有知识、目标位置和事实来源返回 runtime，由 runtime 进入知识审计
   和必要人工裁决。本能力不自行选择或执行 `audit`；审计、批准或写入授权未完成时停止在候选
   状态。

## 受控写入与验证

runtime 交回有效的审计结论、必要批准和写入授权后，更新权威知识及其导航或索引，再从写入
位置回读，并与最终稳定产物、事实来源和当前项目状态核对。

输出“知识沉淀结果”，明确本次是不沉淀、候选待审计、候选未通过，还是已经写入并验证；同时
给出目标位置、实际变化、门禁状态和未解决问题。

## 验证

完成前确认：

1. 只有来自稳定结果和可回查事实、且具有持续价值的变化进入候选。
2. 候选明确现有知识、目标位置、事实来源、差异、冲突、适用范围和验证边界。
3. 结构性问题没有被当作日常沉淀处理，也没有调用 `build`。
4. 知识写入只发生在审计、必要批准和授权完成后，且写后已经回读核验。
5. 没有把过程产物本身当作知识内容，也没有重新执行任务前检索、选择流程、执行任务或替代审计。
