# Build

## 定位

`build` 是四个项目知识建设子能力的唯一入口，只识别建设目标、加载对应资源并回收各自结果。
具体知识由选中的子能力独立建设；本入口不为它们规定共同结构、执行顺序或建设方法。

只接受以下显式入口：

- Harness 首次接入后、启用正常任务流程前要求完成项目知识建设；
- 用户手动要求建设、整理或重新建设某类项目知识。

## 选择并加载子能力

| 建设目标 | 必须完整读取的子能力 |
|---|---|
| 了解并建设真实业务中的角色、对象、问题、价值、流程、规则或业务方案 | [业务知识](references/业务知识.md) |
| 从当前代码等项目事实建立不涉及具体实现细节的项目核心画像 | [项目运行模型](references/项目运行模型.md) |
| 建设某个需求、功能或模块的介绍、规则、边界和稳定设计知识 | [功能知识](references/功能知识.md) |
| 收录数据库、表结构、DDL、迁移 SQL 及其数据语义 | [数据知识](references/数据知识.md) |

按用户要建设的知识对象选择，不按输入材料的文件类型选择。用户指定范围时只读取命中的子能力；
首次接入或用户要求完整建设时分别读取并执行四个子能力；同时命中多类时也分别执行，不合并其
结构、规则或结论。不同选择会实质改变结果且目标仍不清楚时，只确认缺失的建设范围。

选定后先完整读取对应资源，再按该资源自己的执行与验收规则完成工作。每个子能力独立返回知识
候选或已批准的应用结果、产物位置、验证边界和未解决问题；`build` 只按子能力分别汇总状态，
不改写其结果。全部命中项结束后停止，不进入正常任务流程。
