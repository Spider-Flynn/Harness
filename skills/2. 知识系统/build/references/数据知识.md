# 数据知识建设

## 确认结构事实来源

先按项目规则和实际维护方式确认哪一类载体代表当前结构：

- 仓库内受控的 DDL、完整迁移链或 schema 管理文件；
- 获得只读授权后可访问的数据库元数据；
- 能确定版本和适用环境的其他受控 SQL；
- 仅用于辅助理解、仍需核验的说明材料。

不存在适用于所有项目的固定优先级。比较仓库期望结构、指定环境实际结构和既有说明，记录它们
各自的版本、环境和职责。来源不一致时保留差异，不自行选择对使用者最方便的一份作为事实；
没有数据库访问权限时，明确本次只能确认到仓库内结构。

## 建立结构清单与语义说明

按数据库或 schema 建立可定位清单，收录表、字段、类型、主外键、约束、索引、关系以及相关
DDL 或迁移 SQL。对名称不能完整表达的字段、状态值和关联关系，补充来源、实际语义、生命周期、
写入方式与变化边界。测试数据只记录生成或使用所需的元信息，不复制真实业务数据。

优先沿用项目现有数据知识入口；没有可用载体时，按数据库或 schema 建立最小导航，使表结构、
SQL 来源和语义说明可以相互定位。不为尚无结构事实的数据库或表创建空层级。

DDL、迁移和必要 SQL 保留版本与来源。项目已经存在权威文件时，知识入口优先导航到原文件；
只有缺少稳定载体或日常使用确有需要时才整理必要副本，并明确同步责任，避免副本与数据库漂移。

## 排除不应沉淀的内容

临时查询、排障片段、无关 SQL、账号凭据、连接密钥、敏感记录和数据库导出不得进入数据知识。
无法安全判断是否敏感时停止收录，只记录需要人工确认的范围。

## 对照当前结构核验

形成包含现有知识、目标位置、待写入结构与 SQL、事实来源、环境差异和权限边界的候选。候选经
知识审计和必要批准后再应用，并逐项核对知识入口能否定位目标库表，字段、关系和约束是否与
对应权威来源一致，数据语义是否有来源支撑，DDL 或 SQL 是否标明版本和适用环境。发现漂移、
迁移缺口或权限限制时直接列出，不能把该范围标为已建设。
