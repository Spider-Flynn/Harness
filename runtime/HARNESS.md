# Harness 运行合同

> 当前状态：整体结构重构中的初步合同，未启用，尚未经过真实业务任务验证。

本文件是接入业务项目后需要加载的唯一 Harness 运行时合同。它只维护跨能力的公共运行语义，
不复制仓库维护规则、Skill 内部方法、接入脚本实现或 Harness 演进过程。

## 一、加载与边界

1. 先读取业务项目自身适用的用户级和项目级规则。业务项目规则、代码、项目知识和外部系统事实
   仍由业务项目维护；发生冲突时暂停并交给人裁决。
2. 再加载本文件，由 HARNESS 建立当前任务的全局编排视角。
3. 只加载当前任务需要的能力、来源、产物和证据。能力按需组合，不默认经过固定七段链。
4. 本文件不预先决定通过业务项目 `AGENTS.md` 受管片段加载，还是由运行环境在对话前加载；接入方式
   留待平台能力和真实项目试运行确认。

## 二、编排职责

HARNESS 是跨系统调度的唯一所有者。它决定是否进入意图或知识能力、何时调用 `router`、如何按
路线加载和执行能力、何时重新规划，以及如何处理反馈、人工授权和最终结果。

`router` 是软件开发执行路线规划者。它根据已经对齐的需求、当前项目事实和风险，选择具体能力及
顺序，并决定稳定产物、测试策略和审计门禁；它返回路线但不直接调用能力。

Skill 是能力元单位。Skill 只负责被调用后具体怎么完成以及自身产出内容，不判断自己是否应该运行，
不选择下一个能力，也不管理跨系统回流。任何生产代码修改都必须加载 `coding`，但 `coding` 只提供
个性化编码习惯和本机环境使用约束，不负责路线、测试、自检或审计。

## 三、运行循环

1. 读取用户输入和业务项目规则。只有不同理解会实质改变行动时，才调用 `intent` 对齐目标、范围、
   验收、约束和授权缺口；明确请求直接作为路线输入。
2. 使用当前需求和已知事实调用 `router`。如果信息不足以形成路线，Router 只返回会改变路线的事实
   缺口；HARNESS 按需调用 `know` 核验共享事实后重新规划。执行 Skill 可以直接读取完成自身工作所需
   的局部代码和文档，不强制先经过知识系统。
3. Router 输出当前需求的执行路线，HARNESS 按顺序调用路线中的能力。每个节点只获得当前工作必需
   的目标、范围、规则、相关事实、上游产物引用和预期结果。
4. Skill 返回实际结论或修改、正式产物位置、已获得的证据与边界，以及仍缺失或无法继续的事项。
   HARNESS 判断继续当前路线、向用户询问、补充事实或重新规划。
5. 路线完成后，HARNESS 汇总面向需求的实际结果、验证边界、审计结论、人工决定、外部回执和剩余
   风险。文件存在、模型自述、静态检查和 Mock 不能替代对应的真实行为或外部结果。

## 四、执行路线

Router 至少需要决定：

- 是否先进行技术设计，以及设计结论是否形成独立稳定文档；
- 是否需要测试设计，以及测试结论是否形成独立稳定文档；
- 是否采用 TDD，在修改实现前先获得有效失败反馈；
- 是否先定位根因，何时进入生产代码修改；
- 使用 `unit-test`、`it-test`、两者或其他当前可用的真实入口测试能力；
- 是否需要独立审计、审计什么对象，以及审计位于哪一个风险边界；
- 各能力的执行顺序、跳过理由和条件环节。

以下情况才重新调用 Router：用户目标、范围或验收变化；新事实推翻路线依据；当前能力证明路线不可
执行；实际影响面明显扩大；测试、审计或人工反馈要求增加、删除或重做环节。普通节点成功后直接
进入下一项，不为每一步重复规划。

## 五、信息与产物

Harness 不要求通用 Task、Action 或状态对象，也不要求每个任务建立文件。简单任务可以只使用当前
对话和业务项目已有资产；跨能力、跨会话、人工 Review 或独立审计确有需要时，才保留必要的全局进展、
产物引用和证据。

Router 决定是否需要独立设计文档、测试文档等稳定产物，对应 Skill 决定产物的具体内容、结构和方法。
代码、设计、测试和项目知识始终由业务项目在原位置维护；HARNESS 只维护当前路线需要的引用和使用
关系，不复制一套平行正式资产。

## 六、审计边界

Router 决定是否审计、审计对象和位置。`audit` 在不继承产出者推理的独立、只读上下文中，以当前
需求、实际差异、项目规则和执行证据为依据，至少核验：

- 需求是否完整实现，所有修改是否服务本次需求；
- 存量代码或存量行为的修改是否必要，是否存在影响更小的实现；
- 是否混入无关重构、格式化、依赖变化、顺手修复、无用代码、重复逻辑或过早抽象；
- 实现是否保持未要求改变的行为，并遵守项目既有分层和职责；
- 测试与其他证据是否匹配当前风险和真实入口。

审计只扩大到本次改动引入、扩大或直接触达的现实风险。无关存量问题可以单独说明，但不自动扩大
修复范围；没有实际触发路径的理论风险、无边界安全扫描和追求完美方案不得阻断足够简单、正确且
符合项目习惯的实现。Audit 只返回结论和反馈事实，不修复或选择返工能力。

## 七、人工交付与演进

- 人工交付负责 Review、风险接受、授权和外部操作回执。审计通过不等于已经 Commit、Push、PR、
  提测、部署、发布或写入外部系统。
- 项目知识沉淀和 Harness 演进属于不同控制面。Harness 改进必须经过证据、人工批准、实施、独立
  验证、应用或回退，不进入业务任务的 `intent`、`know` 或 `router` 路线。
