# Harness 运行合同

> 当前状态：软件工程领域实例运行时合同。

本文件是接入业务项目后加载的唯一 Harness 运行时合同。它只维护跨能力的公共运行语义与全局调度约束，不复制仓库维护规则与具体 Skill 内部方法。

## 一、加载与优先原则

1. **优先级**：业务项目规则、代码、已有项目知识和外部事实优先。发生冲突时暂停并交由人工裁决。
2. **唯一入口**：由目标项目 `AGENTS.md` 或 `CLAUDE.md` 受管引导块加载本文件，主会话据此建立全局编排视角。
3. **按需加载**：仅加载当前路线必需的能力、事实与产物引用；能力按需组合，不默认穿透固定主链。

## 二、全局编排与操作门禁

- **编排与主体**：HARNESS 是跨系统调度唯一所有者；宿主主会话是默认执行主体；Skill 是按需加载的能力规则单元，不代表独立角色，不自行跨系统流转或选择下一能力。生产代码修改加载 `coding`。
- **外部操作硬授权**：Agent 执行 Commit、Push、PR、部署、发布等外部写入前，必须获得包含当前动作、目标与范围的明确用户授权（用户当前消息明确要求即构成授权，不重复询问）；授权不隐式外推。
- **真实性与受管门禁**：仅依据工具实际输出与外部客观状态报告（文件存在、静态检查或 Mock 不能替代真实执行通过）；受管 Git Hook 强制阻止直接提交 `main`、`master`、`test`、`pre`（不受 `--no-verify` 抑制），命中时提示切换分支，不擅自修改分支策略；任一步失败立即停止后续依赖操作。

## 三、运行循环

1. **意图对齐**：仅在理解歧义会实质改变结果时调用 `intent`；明确请求直接作为路线输入。用户明确要求体系化建库时直接加载 `build`。
2. **路线规划**：调用 `router` 输出执行链路。若缺口属于项目全局共享知识且存在入口，先调 `know` 核验；无知识库时直接跳过，局部读取代码即可。
3. **按序执行**：HARNESS 严格按路线调度所选能力与直接动作；只提供必需上下文，不插入未选环节。
4. **回流与重规划**：局部测试未通过在路线内修正重跑；仅当目标/范围变更、新事实推翻路线依据、能力不可执行或测试/审计要求增减环节时才重新调用 Router。
5. **知识沉淀**：验证与审计通过后，HARNESS 判断是否产生长期共享知识，需要时调用 `know` 提取沉淀；写后回读自检，免常规审计。
6. **汇总交付与复盘建议**：汇总计算机侧事实与验证边界后停止，自然等待用户下一步指令。若任务出现多次返工或审计上限中止等显著系统摩擦，HARNESS 提议用户是否启动 `retro` 复盘。用户审阅后可主动调用 `cr`，HARNESS 不主动调度。

## 四、执行路线规划

- **双轴判断**：Router 独立评估实现复杂度与存量影响；简单局部改动直接修改，不强制设计、测试、校验与审计。
- **按需组合**：从当前可用 Skills 中按依赖组合顺序、测试模式（测试后置、TDD 有效 Red、存量保护）及审计位置（方案高风险时设计前置，最终验证后实现后置）；能力或环境缺失是客观缺口，不得伪称“无需验证”。

## 五、产物与持久化边界

业务代码与测试代码保留在既有位置。Harness 管理的知识与任务产物存放在目标项目 `.harness/` 下，解绑时保留：
- `.harness/know/`：项目长期知识，`README.md` 为唯一总入口。
- `.harness/tasks/YYYYMMDD-任务简名/`：本次任务需保留的独立过程产物（spec、测试设计、测试结果、审计报告及可选 `retro.md`）。
  - **免建规则**：无独立稳定产物的简单直接修改任务，**不创建任务目录，免记 events.jsonl**。
  - **创建与复用**：需要写文件时才创建；同需求的后续对话和修补**严格沿用原目录**；仅全新独立需求且默认命名冲突时才追加短序号（`-1`）。
  - **事件轨迹**：建有任务目录时，随调度追加单行 JSON `events.jsonl`，记录状态迁移与摩擦点：
    `{"ts": "ISO8601", "type": "route_selected"|"action_failed"|"audit_round"|"user_friction", "data": {...}}`，不记录大段代码或思维过程。

## 六、独立审计边界

- **独立只读**：需要审计时，主会话按 `audit` 规则创建干净、只读的 Audit Subagent，不继承产出者的推理过程与期望通过暗示。
- **现实风险与轮次上限**：审计仅覆盖本次修改直接引入或触达的现实风险，不因理论风险或无关存量问题阻断交付；Audit Subagent 只返回结论与证据，主会话负责修改与回复；单次审计最多 3 轮交互，达到上限停止 Agent 交互并如实交付用户裁决。

## 七、演进边界

- **独立新会话与双重触发**：`retro` 是业务项目默认能力，用于复盘 Harness 机制并提供确定性演进答案。必须在**独立新会话**中运行，支持用户主动启动，或由 AI 在交付后提议并在用户确认后拉起新会话注入 Prompt（携带任务目录及产物路径），两会话彻底解耦。
- **证据基线与演进方案**：以任务目录产物与 `events.jsonl` 为不可退缩的第一基线，宿主会话转录为可选辅助；在任务目录下输出 `retro.md`。**必须以最小代价给出明确落地方案**（优化现有 Skill、调整编排、新建能力或增加确定性机制），严守分层以防系统腐化；用户拍板后在当前会话完成迭代验证并记入 `docs/演进记录.md`。
