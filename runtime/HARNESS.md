# Harness 运行合同

> 当前状态：整体结构重构中的初步合同，未启用，尚未经过真实业务任务验证。

本文件是接入业务项目后需要加载的唯一 Harness 运行时合同。它只维护跨能力的公共运行语义，
不复制仓库维护规则、Skill 内部方法、接入脚本实现或 Harness 演进过程。

## 一、加载与边界

1. 先读取业务项目自身适用的用户级和项目级规则。业务项目规则、代码、项目知识和外部系统事实
   仍由业务项目维护；发生冲突时暂停并交给人裁决。
2. 再加载本文件，建立当前任务的运行快照和适用风险约束。
3. 只加载当前任务需要的能力、来源、产物和证据。能力按需组合，不默认经过固定七段链。
4. 本文件不预先决定通过业务项目 `AGENTS.md` 受管片段加载，还是由运行环境在对话前加载；接入方式
   留待平台能力和真实项目试运行确认。

## 二、运行时职责

Runtime 是跨系统编排的唯一所有者，负责：

- 识别当前任务是否需要显式意图对齐、知识、风险路由、执行、审计、人工交付或演进能力；
- 记录能力进入、跳过、停止和返回的原因，以及当前唯一负责系统；
- 交接仍有效的输入、约束、未知项、来源证据、授权和产物引用；
- 根据对象版本、依赖和有效性传播失效，决定局部恢复和重新审计范围；
- 处理反馈、阻塞、等待授权、恢复、终止和最终完成；
- 保存复核和复盘所需的最小运行证据。

功能型 Skill 只完成自身能力，不能自行调用另一个系统、改变公共状态或把未确认信息写成结论。
`router` 只判断技术设计、稳定文档、测试设计和 TDD 等风险路线，不选择或调用具体执行 Skill；
Runtime 根据路线、任务状态和能力清单完成实际组合。

## 三、任务快照与交接

每个任务都应能定位以下最小信息：

- 任务标识、当前意图及其版本；
- 当前状态、负责系统、进入或跳过原因；
- 已确认目标、范围、验收、约束、未知项和授权；
- 参与能力、上下文形态和实际工具；
- 产物对象、版本、来源、依赖、当前有效性和失效原因；
- 验证、审计、人工决定和外部操作的实际证据；
- 阻塞项、恢复条件、终止原因和未覆盖范围。

交接只传递当前节点需要的稳定事实、产物引用和证据，不传递无关全文、临时推理或未采用方案。

## 四、进入、跳过与状态

是否显式调用能力由当前意图、上下文、风险和外部副作用决定。短任务可以在会话内维护快照；
跨会话、高风险或需要复核时才持久化稳定产物与运行证据。

运行至少区分以下状态语义：

- `active`：当前负责节点可以在已确认范围内继续；
- `blocked`：缺少会改变结果的决定、事实、权限或外部条件；
- `waiting_authorization`：候选和条件已准备，但需要人工授权；
- `invalidated`：上游意图、事实、对象或依赖变化使当前产物不能继续消费；
- `terminated`：用户取消、目标消失、条件无法获得或继续会越权；
- `completed`：当前目标已完成，验证、人工决定和必要回执已记录。

状态不是文件是否存在的别名。阻塞必须保留仍有效输入、缺口、唯一负责系统和恢复条件；终止后
不得使用旧产物静默继续。

## 五、产物、失效与反馈

稳定产物必须能关联对象、版本、来源、依赖、适用范围、验证边界和当前有效性。意图、范围、验收、
授权、候选对象或事实发生有效变化时，只使依赖该变化的后继产物和审计结论失效，不默认全链重做。

反馈要说明对象与版本、问题、证据、影响、仍有效输入和恢复条件。Runtime 根据问题性质把它交给
正确负责方：意图变化回到意图接入，事实缺口回到知识，路线不适用回到路由，执行问题回到当前
执行能力，审计或人工反馈则先判断受影响依赖后再重新组合。

## 六、审计、交付与演进

- 独立审计在需要时使用不继承产出者推理的干净上下文，并以只读方式核验具体版本；审计发现问题或
  证据不足均不得通过。
- 人工交付负责 Review、风险接受、授权和外部操作回执。审计通过不等于已经 Commit、Push、PR、
  提测、部署、发布或写入外部系统。
- 项目知识沉淀和 Harness 演进属于交付后的不同控制面。知识写入需经过相应门禁；Harness 改进
  必须经过证据、人工批准、实施、独立验证、应用或回退，不进入业务任务意图链。

## 七、运行证据

只保留复核和复盘需要的最小证据：任务与意图版本、能力进入或跳过、来源使用、产物版本、验证与
审计、人工介入、外部操作、返工、失败原因、耗时、Token、未覆盖范围和最终状态。模型自述不能
替代真实测试、外部结果或人工批准。
