# Harness 运行入口

> 状态：初步实现，未启用；具备手工运行入口和本地接入工具，尚未经过真实业务任务验证。

## 一、职责

本文件是 Harness 的全局装载入口，只维护权威文档的读取顺序和公共门禁，不复制子系统、流程
或 Skill 正文。业务项目规则、项目知识和当前用户决定继续由各自载体维护。

## 二、装载顺序

1. 读取当前业务项目适用的用户级与项目级规则。
2. 读取 [`系统流程.md`](./系统流程.md)，确认当前阶段、有效产物和恢复条件。
3. 读取对应的整体闭环：
   - 单次任务使用 [`整体编排/任务交付闭环.md`](./整体编排/任务交付闭环.md)；
   - 知识与 Harness 演进使用 [`整体编排/系统演进闭环.md`](./整体编排/系统演进闭环.md)。
4. 需要选择执行流程时读取 [`../flows/流程路由.md`](../flows/流程路由.md) 并调用 `router`。
5. 只加载当前节点需要的 Skill、稳定产物、信息源和证据。

## 三、初步运行方式

业务项目通过 `scripts/harness.py init --project <项目目录>` 建立 `.harness/runtime/` 受管入口
和 `.agents/skills/<skill>` 扁平投影后，仍需在业务项目规则中明确：软件开发任务先读取
`.harness/runtime/HARNESS.md`。工具不自动改写业务项目 `AGENTS.md`。

首次接入完成后，启用正常任务流程前必须显式加载 `build`，由它分别选择并执行四个独立知识
建设子能力。后续只有用户明确调用时才再次运行 `build`；正常任务、知识缺口和 `router` 均
不得自动触发。

真实任务由主会话按以下顺序推进：

1. 加载 `intent`，形成当前唯一有效的已确认任务意图。
2. 加载 `know`，形成由可追溯信息元组成、带状态与验证边界的任务信息集合。
3. 加载 `router` 和 `flows/流程路由.md`，只选择一个完整执行流程。
4. 按流程调用执行 Skill，形成稳定产物、候选代码和执行证据。
5. 在不继承产出者推理的干净只读上下文加载 `audit`。
6. 审计通过后由主会话加载 `cr` 组织人工 Review、授权和实际交付。
7. 交付后按系统演进闭环处理持久知识变化，并在证据充分时调用 `retro`；Harness 改进经人工批准后直接进入演进控制面，不进入业务需求链。

需要跨会话保留状态或进行正式试运行时，复制
[`运行记录模板.md`](./运行记录模板.md)，只记录当前有效产物、失效原因、恢复条件和最小
运行证据；普通短任务可以在当前任务上下文中维护同一组事实，不强制创建文件。

## 四、公共门禁

- 用户决定目标、范围、验收、授权和风险接受；项目证据只说明当前事实。
- 未确认意图、未处理的阻断性知识缺口、审计未通过或人工未批准时不得继续交付。
- 功能型 Skill 只完成自身职责；跨系统回流、产物失效、恢复和终止由 runtime 处理。
- 主会话保留用户交互和任务主干；工作包按需使用分支或 Subagent；正式审计必须使用不继承
  产出者推理的干净只读上下文。
- Commit、Push、PR、提测、部署、发布和数据写入等外部状态变化必须获得明确授权，并以实际
  工具结果形成回执。
- 未经过真实任务验证的能力、Agent、脚本和编排不得标记为已启用。
