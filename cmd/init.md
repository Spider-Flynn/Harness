# init：首次接入

帮助用户完成项目绑定，只询问尚未明确、会影响结果的选择。

1. 确定项目路径，缺少时询问；结合目录和用户说明判断是否适用，新项目不要求已有代码。
   未发现 `.git` 时，确认适用后使用 `--allow-non-git`，不替用户初始化 Git，并说明不会安装提交门禁。
2. 读取 `systems/`：只有一个领域系统时自动选择并告知；多个时推荐并确认。
   默认能力不逐项询问，可选能力只在用户需要时选择。
3. 复用项目已有的 `AGENTS.md`、`CLAUDE.md`，两者都有就都接入。两者都没有时，说明
   AGENTS.md 面向 Codex 等 Agent、CLAUDE.md 面向 Claude Code，推荐并询问创建哪个。
4. 已有绑定清单时说明现状，建议改用 `relink`，不直接覆盖或解绑重建。
5. 简述确定的选择，从本仓库调用 `python3 scripts/harness.py init --project "<项目绝对路径>"`，
   补齐已选系统、规则入口及可选能力参数；参数不确定时查 `init --help`。选择在对话中完成，
   不让用户再回答终端交互。
6. 成功后调用同一脚本的 `doctor --project "<项目绝对路径>"`，反馈项目、系统、入口、能力、实际
   投影的依赖、Git 提交门禁和检查结果，说明后续在目标项目会话中使用。软件工程系统的 `rules-know` 随 Skills
   接入，由 Build 与 Know 沉淀按需读取；`build` 可选且先向用户索要信息源，不自动建库或扫描代码。
   接入检查不等于业务主链验证。

失败时解释脚本提示和下一步，不手工修改绑定文件绕过检查。
